# Wallpapers

## What's where

| Collection | Source | Size | License / provenance |
|---|---|---|---|
| **LYNX default** | `assets/wallpapers/lynx-default.png` in this repo | 6 KB | Generated by LYNX, no third-party art. Shown until you pick something else. |
| **Caelestia** | `assets/wallpaper.webp` in [caelestia-dots/shell](https://github.com/caelestia-dots/shell) | 5.6 MB | The only wallpaper Caelestia ships. Repo is GPL-3.0. |
| **ML4W collection** | [mylinuxforwork/wallpaper](https://github.com/mylinuxforwork/wallpaper) | ~790 MB, 220 images | Repo has a GPL-2.0 LICENSE file. Its README calls it a personal collection and lists the wallpaper sites it draws from. |
| **ML4W defaults** | `dotfiles/.config/ml4w/wallpapers` in [mylinuxforwork/dotfiles](https://github.com/mylinuxforwork/dotfiles) | 44 MB, 13 images | 9 of the 13 are byte-identical to images in the collection above; 4 are unique. |

Caelestia has no wallpaper collection of its own. Its screenshots use
third-party wallpapers, and its own community discussion points people to
ML4W's collection and to wallpaper sites.

## Why the wallpapers aren't in this repo

- **Size.** ~840 MB would be downloaded again by every clone of your dotfiles
  and would bloat every `git pull`.
- **Provenance.** Much of it is third-party artwork collected from wallpaper
  sites. Downloading it from its source for your own desktop is what ML4W's
  README itself tells you to do. Re-publishing it inside your own public
  dotfiles repo is a different question, and one LYNX doesn't make for you.

So LYNX downloads them from their upstream repos instead:

```bash
sh ~/dotfiles/lynx/bin/lx wallpaper fetch
```

That puts everything in `~/Pictures/Wallpapers` (Caelestia's default wallpaper
folder too): `caelestia/`, `ml4w/` and `ml4w-defaults/`. Run it again later to
update. The ML4W repos are downloaded as shallow git checkouts, so an update
only fetches what changed.

Keep `~/Pictures/Wallpapers` out of any public repo.

## Using them

| Command / keys | What it does |
|---|---|
| `SUPER + W` | Picker with thumbnails (`lx wallpaper pick`) |
| `SUPER + SHIFT + W` | Random wallpaper (`lx wallpaper random`) |
| `lx wallpaper set FILE` | Set a specific file |
| `lx wallpaper fetch` | Download or update the collections |

The first time you open the picker, thumbnails don't exist yet, so LYNX builds
them in the background (`~/.cache/lynx/thumbs`). With 230-odd images, some of
them 8K PNGs, that takes a minute or two. The next time, they're all there.

Supported formats: jpg, jpeg, png, webp, jxl. The collection's one GIF is
skipped; hyprpaper shows still images.

## What changing wallpaper does

1. `~/.cache/lynx/wallpaper/current` is pointed at the new file, so the choice
   survives reboots.
2. The running hyprpaper switches to it immediately.
3. A resized copy, `~/.cache/lynx/wallpaper/lock.jpg`, is made for the lock
   screen in the background, so locking never waits on a huge image.

4. Everything is recolored to match, also in the background. See
   `theming.md`.

## Why hyprpaper, not awww

awww (formerly swww) has animated transitions and GIF support. hyprpaper is
Hyprland's own daemon, rebuilt with every Hyprland release. It switches
instantly with no animation. LYNX picked hyprpaper for stability, your stated
priority #1. Swapping later only means changing `wallpaper start` and
`wallpaper set` in `bin/lx`.

hyprpaper's own systemd unit requires `graphical-session.target`, which a
Hyprland started from a TTY doesn't activate. So `lx` starts hyprpaper
directly, the same way it starts the bar.
